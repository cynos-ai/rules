# 需求定位与收尾检查方案

承接 [完成边界](../2026-09-07-change-completion-boundary/spec.md)，不改变完成定义或历史保留要求，只补强两个执行入口。

修改前先到项目约定的需求位置查找相关 change，默认位置是 `docs/changes/`；找到后读取三文件，再判断继续还是新建。不能把需求读取留到修改文档时才做，也不新增必填目录索引或状态字段。

完成检查核对本次实施的 Plan：阶段状态和验证记录应与实际结果一致。检查对象不是所有读过的历史 Plan；已完成的旧 change 不回写，纯发布仍只处理发布元数据与事实记录。

验收：原未完成场景确实读到对应 Plan，完成验证后更新同一份记录；已完成后修复仍新建 change，发布准备仍不改旧三文件。以实际文件和工具证据判断，不把偶然一次通过当成普遍遵循率。
