# 更新流程文档与自然语言入口

承接 [安全入口合并](../safe-rule-entry-merge/spec.md)，把 README 的安装/更新执行步骤移入随规则安装的 `docs/rules/update.md`，不维护两份流程。README 只保留使用说明和首次接入短提示词，托管区块按用户意图路由到该文档。

“检查版本”只读，报告本地与最新正式版本，不等于授权更新；“安装、更新、升级或迁移 Cynos Rules”才进入合并流程。结合上下文识别近似表达，无法判断所指时先问，不把其他产品的 rules 更新误认为本任务。没有请求时不自动联网检查。

版本来源固定为官方 GitHub 正式 Release 及其 tag，排除草稿、预发布和未发布分支；一次操作固定目标 tag。联网失败、版本或标记异常时报告并停止，不能猜测最新版本或覆盖本地内容。沿用三方合并、区块外保护和完成后同步版本要求。

旧项目缺少新文档时，从官方最新正式 tag 的 README 获取入口；尚未接入新路由的项目需使用短提示词完成首次升级，不假定它们会自动具备新能力。更新过程不回写已完成 change，整理旧文档和 Git 发布仍需另外授权。

验收以入口可定位、检查与更新授权分离、原安全合并约束保留、旧版接入可用为准；Markdown 只提供指导，不承诺所有 AI 平台都稳定触发。
