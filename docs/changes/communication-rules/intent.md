# 通用沟通与简洁表达规则意图

## 为什么做

Cynos Guidance 与当前 Rules 的工程判断大量重复。Guidance v0.2 又把沟通拆成 discovery、decision-support 和 stress-test 等对话工作流，超出了本项目需要。

仍然缺少的是一组适用于大部分用户沟通的输出组织规则：让 AI 先回答、少说废话、保留完整技术含义，并在压缩会造成歧义时恢复清晰表达。

## 期望结果

1. 大部分面向用户的自然语言回复默认遵守同一组沟通规则；
2. 简单问题直接回答，复杂问题按重要性渐进展开；
3. 删除寒暄、填充、重复结论和无价值的工具过程叙述；
4. 保留否定、条件、例外、数字、单位、技术术语和必要风险；
5. 项目解释仍采用 Guidance v0.1 的结果优先、由外到内结构；
6. 正式文档、代码、Commit、PR、Issue、报告和用户指定格式不被聊天表达规则污染；
7. 作为向后兼容新增内容发布 Cynos Rules `1.1.0`。

## 参考

- Cynos Guidance `v0.1.1` 的 `project-owner-communication`；
- Caveman 的“压缩表达而不压缩技术含义”、精确内容保护和 Auto-Clarity 原则。

只吸收可迁移的核心思想，不复制 Caveman 的品牌语气、破碎语法、强度模式、运行时、Token 营销或其他产品能力。

## 约束

- 不新增 npm 包、Skill、Adapter、模式开关或运行时注入；
- 不把沟通规则扩展成提问、决策、调研或压力测试工作流；
- 简洁不能覆盖正确性、安全性和顺序清晰度；
- 规则本身保持短小，避免为了节省输出而增加过多输入上下文。
