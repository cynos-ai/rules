# 安全合并项目规则入口意图

## 为什么做

目标项目通常已经有 `AGENTS.md`、`CLAUDE.md` 或其他平台规则入口，其中保存技术栈、命令、安全和协作约定。仅要求 AI“合并而非覆盖”仍不足以稳定区分 Cynos Rules 内容与项目原有内容，后续更新可能误删、改写或重复用户规则。

## 期望结果

1. 安装和更新 Cynos Rules 时不覆盖整个项目规则入口；
2. 新安装的 Cynos 内容放入带稳定标记的托管区块；
3. 后续版本只替换可确认属于旧 Cynos 版本的内容；
4. 标记区块之外的用户内容不移动、不重排、不改写；
5. 用户修改过 Cynos 区块时执行版本差异合并，不能静默丢弃本地修改；
6. 无标记的旧 Cynos 版本可根据 `VERSION` 和对应 Git tag 迁移为托管区块；
7. 内容归属不明确、标记损坏或存在多个区块时停止并询问用户；
8. 作为兼容新增能力发布 Cynos Rules `1.2.0`。

## 约束

- 不引入安装器、CLI、Manifest 或运行时；
- 不要求目标项目采用 `AGENTS.md`，继续支持平台原生入口；
- 不依赖文件名判断所有权；
- 不把“语义相似”当作删除用户内容的充分证据；
- 只有整个规则更新成功后才写入新 VERSION 和区块版本。
